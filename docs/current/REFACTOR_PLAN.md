## “干净”的可验收定义
1. 每个状态只有一个可写所有者：UI只呈现/派发意图，业务控制器拥有操作、取消、选择、结果；不靠render顺序改变业务。
2. 应用入口只装配生命周期、消息注册、路由与依赖；具体请求策略、导航回执、功能动作与展示各有窄接口。不能把原巨大闭包搬到新名字下，也不能把整个共享state传给每个模块。
3. 七栏保持完整功能目录；共享会话、身份、导航、资料、目录和时间不复制。禁止feature反向依赖app，禁止循环依赖和跨feature直接操作UI。
4. 提示明确区分短暂反馈、阻塞恢复、操作未确认、进行中任务。文案、原因、用户下一步、所有者、替换/清除条件一致可查；不能用定时消失掩盖未知写入。
5. 不用“正在连接/处理中”掩盖已经停止的任务；旧请求、错误目标、离开界面的迟到回执不得污染当前操作或吞掉待确认结果。
6. 每条已确认修复都有失败→通过的回归。新增文案只通过唯一catalog维护，已批准改动逐键保留前后与理由；旧基线不可整体重录。
7. 生成、测试、打包、源码独立解压均可复现；文档树与真实文件自动/逐项核对。

## 不可改变的稳定边界
- 账号、工作区、document/epoch、expectedTabId及用户点击意图归属不放宽。
- 数据库名/版本/表、已有偏好键、收藏/书签与备份格式保持；不擅自迁移/清理用户资料。
- 标题的预览确认、写入不确定性、串行批次与恢复锁保持；不自动重放修改请求。
- 搜索关键词与日期模式、结果分页与目录来源边界保持；不把错误当空结果。
- 导出当前分支、完整选择、图片/附件、文件格式、任务取消与最终下载回执保持；不得隐藏部分失败。
- 不改变主题、布局、语言选择、用户内容；只针对已证实的误导提示/缺少下一步做小范围规则改善。
- 不写旧路径别名、兼容壳、重复实现或长期feature flag；删除旧实现须同时更新消费者、生成器和测试。

## 执行分工与阶段
1. 版本同步（已完成并单独提交）。
2. 保存此方案、只读审查和确定模块接口；然后并行按互斥文件所有权实施。
3. 侧栏：抽离请求运输、导航所有权与精确回执、上下文/资料协调、栏目动作与渲染编排；修复错误目标提前消费导航完成标记。
4. 搜索/导出：拆分状态控制、请求编排、选择模型、任务/资源生命周期与纯呈现；移除绘制导致业务状态变更的隐式耦合，保持公开功能契约。
5. 后台/网页：按准入、路由处理、快照观察、消息分发分离运行时；保持原消息格式和证据检查顺序。
6. 提示治理：统一可测试的生命周期契约与安全原因关联。修复已确认的备份/标题未确认状态被栏目切换清除、连接重试耗尽仍假忙碌等覆盖空白；不把重要恢复信息变成易消失toast。
7. 强化依赖边界与组合根检查；补充功能不变及异步交互回归。旧测试只适配真实模块入口，不删断言/跳过场景/伪造成功。
8. 更新完整职责树、功能接口、文案与交互索引、开发说明。执行全量Node、双浏览器、七栏四语言与异常路径检查。
9. 生成0.5.0候选包，独立解压离线运行；确认0.4.0未改、全部变更存Git、明确仍未覆盖的真实账号验收。

## 交互验收场景
- 快速切换栏目/会话/账号、连续点击、迟到成功/失败、错误目标回执、正在连接→停止→重试。
- 备份恢复提交后切出再回、丢回执、再次读取失败：不能丢失“结果未确认”，不得自动重写。
- 标题修改丢回执、核对失败、批次暂停/继续：状态与恢复入口一致，不能只剩普通读取失败。
- 搜索新查询替代旧查询、日期来源与导出选择、短暂错误到时清除：不复活旧提示。
- 导出切模式/栏目、后台任务、取消、部分资源异常与最终下载确认：选择及结果不被绘制顺序改变。
- 四语言、键盘焦点、主题、页面刷新准入和原生导航保持。

### 已确认缺陷

1. 原生网页引用被序列化器当作文件引用，内部编号进入 Markdown/TXT/PDF；字符串图片标记未成为媒体块，关闭媒体后仍残留。
2. 来源标题与 URL 独立取值，可能把正确的输入配错；分组 items 只保留第一项。
3. PDF 表格绕过普通段落的引用处理，产生方框；预览与正式文件不一致。

### 责任边界与修复顺序

1. 原生引用适配：独立纯模块识别 ChatGPT 引用/图片元数据，依据精确标识或 matched_text 关联，不按索引或标题猜链接。来源标题与 URL 必须来自同一个来源对象，展开分组来源。
2. 统一可读源内容：网页引用转成普通 Markdown 链接；图片标记转成现有 image/resource 模型，复用媒体开关。无明确来源的引用不伪造链接、不输出内部 ID；有明确文件名才保留文件名。正文与代码示例区分，代码字面量不当作运行标记删除。
3. 格式呈现：engine 只消费已规范化内容，不再认识 ChatGPT 私有标记；共用行内链接呈现规则，Markdown 保留链接，TXT/PDF 保留可读标题与完整地址。PDF 表格、段落与预览使用一致规则。
4. 接线与文案：显式加入 MAIN/计算线程/侧栏及测试装配，退役错误的 exportFileCitation 导出模板，不新增弹窗或提示卡片。
5. 扩大检查：当前/批量/书签、七个选项、四种格式、资源、取消、失效结果、预览和保存，只有具备复现证据的额外 BUG 才修。
6. 独立审查：由未写对应实现的审查者检查契约、数据保真、开关、代码字面量与回归；发现问题先补复现再修。

### 验收门槛

- 新增从原生元数据到实际导出结果的测试，不能只替换用户生成文件中的字符串。
- 已知内部标记用例不再作为读者正文残留；多来源对应正确，缺少元数据时不编造来源。
- 开关关闭后媒体与相应资源读取确实移除；代码字面量、普通链接和已有正文不被误删。
- 实际 PDF 字节/编码及链接、Markdown ZIP 资产成员验证，不只看预览。
- 构建、完整 Node 门禁、隔离 Chrome/Edge 专项、四语言/七栏回归、架构及生成物检查。
- 真实账号、已安装扩展与合成浏览器验证必须分开报告；没有实测的不声称通过。
- 完成后更新本文件结果，打包安装包/源码包并记录 SHA256，保存 Git。

### 扩大审查后补充的修复项

- 普通 Markdown 图片原先只是段落文字，绕过媒体开关；统一变成图片块，代码示例不转换。
